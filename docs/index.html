1. 사람은 어디에 있나: HOTL 과 HITL

두 방식을 모두 쓴다. 기본은 루프 위(Human-on-the-loop, HOTL)다. 에이전트가 계획·구현·테스트·리뷰·머지를 진행하고, 사람은 규칙을 정하고 결과를 보다가 예외에만 끼어든다. 되돌릴 수 없는 행동, 사람 몫의 행동, 사용자 설정과 자격 증명은 루프 안(Human-in-the-loop, HITL)이다. 그 단계에서 에이전트가 멈추고 사람이 승인하거나 직접 한다.

HOTL 사람이 감독하고 예외에만 개입

  • 혼자 도는 카드는 검증된 PR 을 묻지 않고 머지한다. 사람이 hold 를 걸면 멈춘다.
  • 프로그램의 머지 정책 기본값 autonomous: 워커가 orch land 로 착지한다.
  • 사람은 brief 현황 보고와 대시보드의 결정·권한 창·받은편지함에서 상태를 보고 답한다.

HITL 사람이 그 단계를 승인

  • 머지 정책 human-gate: 워커가 READY 에서 멈추고 사람이 게이트를 풀어야 착지한다.
  • 사용자 설정 쓰기: 에이전트는 diff 만 보이고, 사람이 ! 한 줄로 적용한다.
  • 자격 증명, 되돌릴 수 없는 행동과 사람 몫의 행동 앞에서는 멈추고 묻는다.

기본값은 사람을 거치지 않는 쪽이다. 머지 전에 직접 보고 싶으면 hold 나 human-gate 를 미리 건다. 대시보드는 Orca 를 전제로 하므로, Orca 없이 쓰면 사람이 보는 곳은 채팅의 현황 보고와 트래커·노트로 줄어든다.

2. 전체 구조

일은 위에서 아래로 흐르고, 보고는 아래에서 위로 올라온다. 오른쪽 장치들은 그 흐름을 감시하고, 거르고, 보여 준다.

  1. 사람채팅, 대시보드, ! 명령. 규칙과 머지 정책을 정한다.
  2. 지시
  3. 오케스트레이터 세션orchestrate. 라우팅·판단·보고만 한다. 조사는 서브에이전트에, 편집은 리드·카드에 넘긴다.
  4. 프로그램 하나
  5. 리드프로그램 하나를 완료 조건까지. orch land·orch stage.
  6. 티켓 하나 (리드 없이 dispatch-card 로 바로 갈 수도 있다)
  7. 카드 / 워커Orca worktree 하나에 티켓 하나. deliver-ticket 으로 일하고, 끝나면 위로 보고한다.
  8. 결과
  9. 결과물: PR · 티켓 · 노트GitHub(orch land), Linear·Jira(use-tracker), Obsidian·Markdown 폴더(use-notes).
  • 대시보드 orch-dash모델 호출 없이 Orca·GitHub·트래커·원장을 읽어 보여 준다. 결정과 권한 창에 여기서 답한다. 기본으로 127.0.0.1 에 바인드한다.
  • 정기 자동화 (세션 밖)Orca automation 은 precheck 가 모델 없이 거르고, 할 일이 있을 때만 모델 회차가 돈다. LaunchAgent 는 모델 없이 돈다.
  • hook (모든 세션)도구 호출·프롬프트·세션 시작·멈춤마다 결정적 규칙으로 허용·거부·알림. 위임 강제, 사용량 확인, 완료 주장 검사, 문체 검사 등.
  • 세션 안 감시받은편지함 대기 하나(orch wait 또는 orch inbox --wait)와 카드 화면 감시(orch watch-cards).

카드는 Orca(여러 Claude Code 세션을 worktree 별 터미널로 띄우는 멀티 에이전트 IDE)에서 일 하나를 맡은 세션이다. 프로젝트 안에서 티켓 하나를 맡은 카드를 워커라고 부른다. deliver-ticket 은 Orca 카드 밖에서도 돈다.

6. 안전장치

hook 10개

hook하는 일
guard이 플러그인 스킬과 orch 명령 일부를 허용하고, 다른 터미널의 메일함 읽기와 sleep 폴링 루프를 거부한다
orchestrator_guard최상위 오케스트레이터 본인 스레드의 직접 작업을 거부하고 위임 경로를 알린다
pressure_gatePC 사용량이 위험이면 무거운 작업 시작을 거부한다
prose_checkPR·커밋·티켓 본문의 금지 문체를 알린다. 막지 않는다
claim_check코드를 고치고 아무것도 돌리지 않은 채 "고쳤다"고 하면 한 번 막는다
onboard설정되지 않은 PC 에서 setup-pc 를 제안한다
reorient오케스트레이터·리드 세션에 다시 읽을 규칙을 넣는다
decision터미널에서 답한 대시보드 결정을 닫는다
permission권한 창을 대시보드에서 답할 수 있게 기록한다. 결정은 내리지 않는다
request_log오케스트레이터·리드가 받은 사람의 요청을 요청 원장에 열린 항목으로 남긴다

정리가 넘지 않는 선

reap-resources 가 먼저 목록을 만들고 그 목록만 정리한다. 세부 대상과 예외는 reap-resources.

  • 파일은 휴지통으로만 보내고, 휴지통을 비우지 않는다.
  • 정기 정리 janitor 는 compose 를 down 까지만 한다. -v, prune, 볼륨·이미지 삭제는 하지 않는다.
  • 열린 PR, 커밋하지 않은 변경, 푸시하지 않은 커밋, 진행 중인 턴이 있는 카드는 대상이 아니다. 메인 체크아웃도 아니다.
  • 목록에 올린 대상만 정리한다. 거부되면 우회하지 않고 사람에게 넘긴다.

설정이 없으면 끄거나 멈추고 묻는다

스킬은 노트 저장소·폴더·채널을 추정하지 않는다. 설정 키가 없으면 그 기능을 켜지 않는다. 키별 동작은 docs/configuration-migration.md.

7. 설치

  1. Claude Code 세션에서 /plugin marketplace add JeongJaeSoon/agent-skills, /plugin install agent-skills@jeongjaesoon.
  2. 새 세션을 연다. 설정되지 않은 PC 임을 알아채고 setup-pc 를 제안한다.
  3. 받아들이면 에이전트가 체크아웃·권장 설정·정기 자동화를 준비하고, 바뀔 내용을 파일별 diff 로 보인다.
  4. 사람은 그 diff 를 읽고 ! 한 줄과 권한 창 승인만 한다.

셸에서 직접 하는 방법(scripts/setup.py dry run 뒤 --apply <해시>)과 갱신은 docs/new-pc.md, 사람의 한 줄이 남는 이유는 docs/zero-command-setup.md.

근거: README, docs/skills.md, docs/automation.md, hooks/hooks.json, skills/*/SKILL.md. 내용이 다르면 저장소 쪽이 맞다.
